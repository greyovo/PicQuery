# MobileCLIP2：候选去重与图像预处理优化验证

2026-09-13，本轮保留 MobileCLIP2-S0 / dfndr2b 模型、图像 FP32 / 文本动态 INT8 精度和既有运行库，只优化重复编码与内存使用。两个后端共 46 个单元测试、10 个真机测试通过；同一黄金样本的图像和文本向量与上一轮 App 均逐元素一致。

## 改动范围

- 搜索候选与 BPE 分词共用大小写、连续空白规范化函数。`Dog` 和 `dog` 只编码一次，保留首个候选的写法和顺序；不同的翻译、中文别名仍保留。翻译照常执行，没有对英文跳过翻译。
- 图像预处理复用像素和 RGB 通道临时数组，以一次批量写入替代逐元素 `FloatBuffer.put`；缩放、中心裁剪、RGB `[0,1]` 和 NCHW 布局不变。循环内缓存 lazy 数组引用，避免重复访问其委托属性。
- 图像编码器在会话锁内复用直接输入缓冲区，跨照片和批次复用；独立 `preprocess` 调用仍返回互不覆盖的输出。预处理临时数组由专用锁保护，关闭编码器时清除缓冲区引用。
- 设置页、ONNX 和 TFLite 会话读取统一线程配置：ONNX 图像/文本 4/4，TFLite 原生 XNNPACK 4/2。简化 delegate 配置控制流；LiteRT 1.4.1 与固定 C API ABI 没有升级。
- 重整中英文 README，以当前资产、构建、索引与验证步骤为主；旧模型入口移到历史参考，移除未经支持的速度承诺。既有报告和原始数据保留各自历史含义。

## 独立预处理计时

设备为 Pixel 8a / Tensor G3 / Android 17，4 KB 内存页。主对照使用同一个 ONNX 变体、相同独立 `preprocess` API：每个尺寸预热 20 次、记录 100 次，Debug instrumentation 不启动 Activity。Bitmap 创建在计时之外；包含 API 自己的输出分配、缩放、裁剪和通道转换，不包含模型推理、翻译、数据库或 UI。

| 输入 | 优化前 P50 / P95 ms | 最终 P50 / P95 ms |
|---|---:|---:|
| 256×256 | 24.132 / 24.648 | 0.802 / 0.852 |
| 1024×640 | 25.574 / 26.308 | 1.855 / 1.961 |

P50 为 `statistics.median`，偶数样本取中间两项均值；P95 为 nearest rank。原始记录：[优化前](preprocessor-before.json)、[最终 ONNX 变体](preprocessor-after-onnx.json)、[验证汇总](verification.json)。只有单轮前后对照，不能把该下降幅度换算成整个 App、索引或搜索的提速倍数。

中间版本已改成批量写入，但尚未把循环中的 lazy 数组引用保存为局部变量，256×256 / 1024×640 的 P50 分别为 3.060 / 4.243 ms；其[原始数据](preprocessor-pass1.json)保留作过程证据。最终 TFLite 变体也运行同一预处理测试，P50 为 0.795 / 1.878 ms，见[原始数据](preprocessor-after-tflite.json)。独立 API 仍分配返回缓冲区，因此此计时没有单独量化图像编码器复用直接输入缓冲区的收益。

## 回归验证

| 检查 | 结果 | 证据 |
|---|---|---|
| 单元测试 | ONNX 23 + TFLite 23，共 46；0 failures / errors | [构建日志](build.log)、[汇总](verification.json) |
| 真机测试 | 每个后端 5 个，共 10 个通过 | [ONNX](onnx-after.log)、[TFLite](tflite-after.log) |
| 同一黄金样本与上一轮向量比较 | 两后端图像、文本各 512 维，最大绝对差均为 0 | [ONNX 输出](parity-onnx.json)、[TFLite 输出](parity-tflite.json)、[上一轮报告](../pixel8a-app/实际运行报告.md) |
| 分词、文本资产哈希、官方/量化参考余弦 | 全部通过 | 两份 parity JSON |
| TFLite 原生线程池 | 图像、文本均存在，配置 4/2 | [汇总](verification.json) |

四个预处理测试覆盖 RGB/NCHW 精确值、中心裁剪的 ties-to-even 舍入、输出独立性、批次顺序、空批次、输入图片未被回收，以及并发调用结果一致。优化前和中间版本的日志各记录这 4 个测试；最终每个后端的 5 个测试为这 4 个加 1 个编码器测试，共 10 个。编码器测试还检查批处理与逐张一致、重复输出稳定和关闭后拒绝调用；本轮每塔预热 3 次、计时 10 次，这些调用不构成持续性能基准。

候选去重回归测试先在旧实现上出现预期的 4 项失败，再修改实现并通过完整测试；[预期失败日志](expected-regression-failures.log)是证明测试能够捕获旧行为的历史记录，不是最终构建失败。

最终构建成功：32 秒，194 个任务，其中 58 个执行。双变体 Lint 均为 0 errors、95 warnings、5 hints。Detekt 只读运行，`autoCorrect=false`，发现 26 条，较前一轮减少 1 条；`ignoreFailures=true`，不能将任务完成解释为零告警。代码审查未发现阻塞问题。记录见[构建日志](build.log)、[Detekt 输出](detekt.txt)及[含最终 APK 哈希的汇总](verification.json)。

## 复现与边界

使用 JDK 17、Android SDK 36、NDK 29.0.14206865、CMake 3.22.1 及现有模型资产。从仓库根目录构建主 APK、测试 APK并运行静态检查：

```powershell
.\gradlew.bat :app:assembleOnnxDebug :app:assembleTfliteDebug :app:assembleOnnxDebugAndroidTest :app:assembleTfliteDebugAndroidTest :app:testOnnxDebugUnitTest :app:testTfliteDebugUnitTest :app:ktlintKotlinScriptCheck :app:lintOnnxDebug :app:lintTfliteDebug
```

按[主 README](../../../../README_zh.md#验证命令)的显式 `adb -s DEVICE_SERIAL install -r` 步骤安装两个 App 及各自测试 APK，保留已有索引。精确复现本轮编码器采样时，用以下参数运行两类测试：

```powershell
adb -s DEVICE_SERIAL shell am instrument -w -r -e class me.grey.picquery.feature.MobileCLIP2InstrumentedTest,me.grey.picquery.feature.MobileCLIP2PreprocessorTest -e sampleCount 10 -e warmupCount 3 me.grey.picquery.mobileclip2.onnx.test/androidx.test.runner.AndroidJUnitRunner
adb -s DEVICE_SERIAL shell am instrument -w -r -e class me.grey.picquery.feature.MobileCLIP2InstrumentedTest,me.grey.picquery.feature.MobileCLIP2PreprocessorTest -e sampleCount 10 -e warmupCount 3 me.grey.picquery.mobileclip2.tflite.test/androidx.test.runner.AndroidJUnitRunner
```

预处理测试自身固定为每尺寸 20 次预热、100 次采样。产物位于各 App 的 `files/mobileclip2_device_report.json` 和 `files/mobileclip2_preprocessing_report.json`；新实验应另存目录，勿覆盖已有证据。本机目标序列号为 `43231JEKB22129`。

本轮未升级模型或依赖，也未重跑完整识别数据集。向量逐元素一致仅针对同一黄金样本；小相册查询不代表通用检索精度。没有新的端到端持续负载测试；Release/R8、GPU/NPU、其他真机及整包 16 KB 页兼容性仍未验证。复用缓冲区需要串行保护；编码任务在每张图前协作检查取消状态，等待 JVM monitor 本身不可取消。
